## Flujo de Trabajo

Los endpoints son encadenados: cada uno necesita un ID que devuelve el anterior.

<Steps>

1. [Obtener token](/authentication/)

2. [Obtener Cliente](/channels-chat/cliente/) → te da el `cus_id`

3. [Obtener Tickets](/channels-chat/tickets/) → con el `cus_id`

4. [Obtener Mensajes](/channels-chat/mensajes/) → con el ticket

5. [Obtener Medios](/channels-chat/medios/) → si el mensaje trae multimedia

</Steps>

## Errores Comunes

| Código | Mensaje | Posible Causa |
|--------|---------|---------------|
| 400 | Error: No hay datos | Cliente o canal no encontrado |
| 200 | No existe customer para consulta de tickets | `customer_id` inválido |
| 401 | No autorizado | Token expirado o inválido |

:::caution
El segundo caso devuelve **200**, no un código de error: un `customer_id` inválido no rompe la llamada. Validá el cuerpo de la respuesta, no solo el status.
:::

## Tips

- Usá `last_msn_id` para paginar mensajes
- `msn_tipo_str` indica el tipo de contenido multimedia
- El endpoint de medios retorna binario: manejá el `Content-Type` correctamente
